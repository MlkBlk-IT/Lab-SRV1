1. RESUME EXECUTIF

Ce document couvre la Phase 2 du projet de durcissement du laboratoire Hyper-V. Il definit une strategie de securite definitive pour le serveur SRV1 (Windows Server 2025), assurant une isolation totale entre l'hote physique et l'infrastructure virtuelle.

Objectif principal : Durcir SRV1 en une seule execution, de maniere perenne, sans jamais compromettre la securite du laptop hote.

Principe fondamental : ZERO communication reseau entre l'hote (laptop) et l'integralite du lab (SRV1 + VMs).

Resultat attendu : Une seule execution du script -> une securite perenne. Le serveur s'adapte automatiquement aux futurs roles ajoutes.

4. SCRIPT DE DURCISSEMENT

Le script PowerShell 06-Durcissement-SRV1-Strategique.ps1 automatise l'integralite du durcissement en une seule execution.

Fichier : 06-Durcissement-SRV1-Strategique.ps1

4.1 Etapes du script

Verification des privileges Administrateur

Sauvegarde automatique de la configuration actuelle (.wfw)

Application de la politique Block Inbound sur tous les profils

Autorisation ICMPv4 depuis le LAN (192.168.50.0/24)

Blocage de l'hote (192.168.137.1 et 10.0.0.0/24)

Blocage des ports RDP, WinRM, SMB et NetBIOS

Sauvegarde de la configuration finalisee (.wfw)

Tests post-durcissement (5 tests automatises)

Rollback automatique en cas d'echec d'un test

4.2 Principe de fonctionnement

Le durcissement s'effectue au niveau des PORTS, pas des SERVICES. Les services Windows (DHCP, DNS, RRAS) conservent leurs regles propres. Seuls les ports sensibles et le trafic hote sont cibles.

AVANTAGE CLE : Le serveur s'adapte automatiquement aux futurs roles ajoutes. Aucune modification du script n'est necessaire lors de l'ajout de nouveaux services.

5. PROCEDURE D'APPLICATION

Suivez scrupuleusement les etapes ci-dessous :

Etape 1 - Ouvrir une session sur SRV1

Connectez-vous localement ou via la console Hyper-V.

Etape 2 - Lancer PowerShell en tant qu'Administrateur

Clic droit sur PowerShell -> Executer en tant qu'administrateur.

Etape 3 - Se placer dans le dossier du script

cd C:\SRV1-Hardening

Etape 4 - Executer le script

.\06-Durcissement-SRV1-Strategique.ps1

Etape 5 - Attendre la fin

Duree estimee : environ 30 secondes.

Etape 6 - Verifier les resultats

Tous les tests doivent afficher OK en vert.

IMPORTANT : Ne pas interrompre le script pendant son execution. En cas d'echec, le rollback automatique restaure la configuration initiale.

6. TESTS DE VALIDATION

Le script integre 5 tests post-durcissement. Chaque test doit retourner OK :

Test

Objet

Description

Test 1

Politique Block Inbound

Verifie que la politique est bien "BlockInbound,AllowOutbound" sur tous les profils.

Test 2

Hote bloque (192.168.137.1)

Confirme l'existence de la regle bloquant l'adresse IP de l'hote.

Test 3

RDP bloque (3389)

Verifie la presence de la regle bloquant le port 3389/TCP.

Test 4

WinRM bloque (5985, 5986)

Verifie la presence de la regle bloquant les ports WinRM.

Test 5

SMB bloque (445)

Verifie la presence de la regle bloquant le port SMB.

Resultat attendu : Si tous les tests passent : message de succes. Si un test echoue : rollback automatique.

7. SAUVEGARDES ET ROLLBACK

7.1 Fichiers de sauvegarde

SRV1_Backup_YYYYMMDD_HHMMSS.wfw - Configuration avant durcissement

SRV1_Hardened_YYYYMMDD_HHMMSS.wfw - Configuration apres durcissement

7.2 Procedure de rollback manuel

Si necessaire, restaurez la configuration initiale :

netsh advfirewall import "C:\FirewallBackups\SRV1_Backup_*.wfw"

ATTENTION : Remplacez * par le timestamp exact. Le rollback manuel ecrase toutes les regles actuelles du pare-feu Windows.
