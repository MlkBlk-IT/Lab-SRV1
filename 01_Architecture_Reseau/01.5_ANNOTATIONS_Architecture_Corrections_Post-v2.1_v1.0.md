# INTRODUCTION


Ce document d'annotations recense les écarts identifiés entre la documentation d'architecture (v2.1) et l'état réel du lab au 2 août 2026. Chaque écart est documenté avec sa cause, sa justification, et l'action corrective ou de traçabilité requise. Ce document garantit la cohérence du portfolio malgré l'évolution rapide du projet.

▸ Principe de traçabilité

Tout écart entre la documentation et la réalité doit être annoté. Aucune modification n'est faite silencieusement sur le terrain sans être reflétée dans un document de suivi. C'est la règle d'or du portfolio professionnel : la documentation est aussi importante que l'infrastructure.


# ANNOTATION 1 : IP de SRV2 — Écart Architecture vs Réalité



## 1.1 Écart identifié


Le document d'architecture DOC-ARCH-001 (v2.1), section 1.4 'Inventaire des Machines Virtuelles', attribue à SRV2 l'adresse IP 192.168.50.2 avec le statut 'À définir (Alma / Ubuntu / Win 2022)'. Le document 05.1_DOC-SRV2-001 (v1.0, 2 août 2026) confirme SRV2 comme Windows Server 2022 avec l'IP 192.168.50.17.

[ANNOTATION] Écart confirmé par lecture croisée des documents 01.4 (v2.1) et 05.1 (v1.0) le 2 août 2026 à 02:05.


## 1.2 Cause de l'écart


L'IP 192.168.50.2 a été réservée dans le plan initial (v1.0/v2.0) comme adresse statique pour le futur SRV2. Lors du déploiement réel de SRV2 (Phase 5, 2 août 2026), l'IP 192.168.50.17 a été choisie pour éviter tout conflit avec le scope DHCP actif (192.168.50.10 – 192.168.50.200) et pour libérer 192.168.50.2 en cas de besoin futur (second serveur applicatif ou DC secondaire).

[ANNOTATION] Décision prise lors du déploiement SRV2 le 2 août 2026. Le scope DHCP n'a pas été modifié.


## 1.3 Justification


192.168.50.2 est dans la plage d'exclusions manuelles du scope DHCP (réservée pour IPs fixes).

192.168.50.17 est dans la plage d'attribution DHCP mais a été configurée en statique sur SRV2 après exclusion du scope.

Cette approche évite tout conflit DHCP/lease et préserve 192.168.50.2 pour un usage futur.

[ANNOTATION] Le scope DHCP (192.168.50.10–192.168.50.200) n'inclut pas 192.168.50.2, mais l'exclusion de 192.168.50.17 n'a pas été formellement documentée dans le DHCP. À vérifier.

Le document DOC-DOM-001 (v1.1) présente un plan d'action complet pour la Phase 2 (AD DS) avec 7 étapes numérotées, commandes PowerShell, et checklist de validation. Cependant, aucun document de preuve d'exécution (logs, captures, incidents) n'est présent dans l'arborescence. Les prérequis PRQ-01 à PRQ-05 ne sont pas formellement validés.

[ANNOTATION] Confirmation par scan arborescence du 2 août 2026 à 00:16 : aucun fichier de log d'exécution Phase 2 dans 09_Exports ou 03_Identite_Domaine_AD.


## 2.2 Cause de l'écart


La Phase 1 a été finalisée (script v3, 7/7 tests OK) entre la publication de DOC-ARCH-001 v2.1 (1er août) et la génération de DOC-DOM-001 v1.1 (1er août soir). Cependant, la Phase 2 n'a pas encore été exécutée car les prérequis (notamment snapshot Hyper-V et mot de passe DSRM) n'ont pas été validés.

[ANNOTATION] Le statut 'En cours' de la Phase 1 dans DOC-ARCH-001 v2.1 est obsolète — la Phase 1 est terminée. Cette annotation corrige ce point.


## 2.3 Justification


La séquence hardening → AD DS est non négociable (règle d'or du document).

Un DC mal durci expose l'intégralité des credentials et des stratégies.

Le snapshot 'Pre-Phase2-DC-Promotion' est un prérequis strict (PRQ-02) — il n'existe pas encore.

[ANNOTATION] Le snapshot est la seule méthode de rollback fiable pour une promotion DC. Sans snapshot, le risque de re-création from-scratch est élevé.

# ANNOTATION 3 : État Phase 5 (SRV2) — Déploiement en cours



## 3.1 Écart identifié


Le document DOC-ARCH-001 (v2.1) liste SRV2 avec le statut 'À déployer' et l'OS 'À définir'. Le document 05.1_DOC-SRV2-001 (v1.0) confirme SRV2 comme Windows Server 2022 (FR) en déploiement. Cependant, le déploiement est actuellement bloqué sur l'erreur Windows Update 0x80070057.

[ANNOTATION] Erreur 0x80070057 observée le 2 août 2026 lors de l'installation des mises à jour cumulatives sur SRV2. DISM /RestoreHealth en cours.


## 3.2 Cause de l'écart


L'erreur 0x80070057 (ERROR_INVALID_PARAMETER) est une erreur générique Windows Update souvent causée par : (1) corruption du store de composants Windows (WinSxS), (2) espace disque insuffisant, (3) conflit de pilote, ou (4) image ISO d'installation endommagée. DISM /RestoreHealth tente de réparer le store de composants.

[ANNOTATION] DISM lancé avec la commande : DISM /Online /Cleanup-Image /RestoreHealth. Source de réparation : image ISO Windows Server 2022 montée.


## 3.3 Justification


SRV2 doit être complètement à jour avant l'installation des rôles IIS/MariaDB/SMB.

Une VM vulnérable mais non patchée est une cible irréaliste — les failles doivent être volontaires, pas accidentelles.

L'erreur 0x80070057 est documentée ici comme incident technique réel, pas comme faille de sécurité.

[ANNOTATION] Cette erreur est un incident de déploiement, pas une faille de sécurité. Elle doit être résolue avant de continuer la configuration des failles volontaires.
