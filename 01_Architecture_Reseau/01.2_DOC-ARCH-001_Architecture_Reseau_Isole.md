# 1. RÉSUMÉ EXÉCUTIF


Ce document présente la conception architecturale d'un laboratoire réseau isolé déployé sur Hyper-V, centré sur un serveur Windows Server 2025 agissant comme cœur d'infrastructure (Domain Controller, DHCP, DNS, NAT/SMB, RRAS). L'objectif est de créer un environnement réaliste permettant la pratique du pentest, de la défense réseau (Blue Team) et de la collaboration offensive/défensive (Purple Team), tout en documentant chaque étape pour constituer un portfolio professionnel démontrant la maîtrise des concepts d'architecture, de sécurité et de virtualisation.

📌 Annotation — Portfolio : Ce document sert de pierre angulaire au portfolio. Chaque phase de construction sera documentée de manière identique, créant une traçabilité complète de l'évolution des compétences et de la maturité de l'infrastructure.


# 2. CONTEXTE ET OBJECTIFS PÉDAGOGIQUES



## 2.1 Contexte


Première expérience d'administration Windows Server. Le projet est construit from-scratch sur une infrastructure Hyper-V hébergée sur Windows 11 Pro. L'approche privilégie la compréhension théorique avant toute implémentation technique.


## 2.2 Objectifs d'Apprentissage


Maîtriser les fondements de l'administration Windows Server 2025 (rôles, services, sécurité)

Comprendre et implémenter Active Directory, Kerberos, et les GPO

Concevoir une architecture réseau avec segmentation logique

Pratiquer le Red Team (techniques d'attaque) et le Blue Team (détection, réponse)

Développer une approche Purple Team (itération attaque/défense)

Documenter chaque phase pour constituer un portfolio professionnel crédible

📌 Annotation — Pédagogie : La progression suit le principe 'théorie → pratique → documentation'. Aucune commande n'est exécutée sans compréhension préalable du concept sous-jacent. Cette discipline garantit une expertise réelle, pas une simple répétition de procédures.

## 4.2 Flux de Données


Les VMs clientes (Win10, Win11, Ubuntu, Alma OS, OpenKylin) communiquent entre elles via le vSwitch_LAN. Le trafic vers Internet transite obligatoirement par SRV1, qui applique la translation d'adresse (NAT). Aucune VM ne possède d'interface directe sur le réseau physique.

📌 Annotation — Double NAT : Le double NAT isole totalement le lab des scans réseau de la box FAI et permet de faire tourner un contrôleur de domaine sans risque de conflit DNS avec le resolver du routeur physique. C'est une approche systématisée sur tous les labs d'entreprise.

# 6. PLAN DE SEGMENTATION RÉSEAU



## 6.1 Choix Architecturaux


Une seule zone LAN (192.168.50.0/24) a été retenue pour la phase initiale. La segmentation physique (VLANs) ou logique (sous-réseaux multiples) est volontairement différée pour maintenir la complexité maîtrisable. SRV1, via RRAS, pourra assurer le routage inter-zone si une segmentation ultérieure est décidée.

## 6.3 Options DHCP Critiques


Option 003 (Routeur / Passerelle par défaut) : 192.168.50.1 — Pointe vers SRV1 (NAT)

📌 Annotation — DHCP comme levier de contrôle : Le DHCP est le premier point de contact de toute machine sur le réseau. En contrôlant les options 003 et 006, SRV1 impose sa position de routeur et de résolveur DNS. C'est un point de contrôle fondamental : un attaquant qui compromet le DHCP redirige tout le trafic vers sa machine (attaque DHCP spoofing). D'où l'autorisation AD et la surveillance.


# 7. SCÉNARIO D'ATTAQUE ET KILL CHAIN



## 7.1 Objectif de l'Attaquant


L'objectif pédagogique est de reproduire une chaîne d'attaque réaliste : compromission d'une cible faible, mouvement latéral via credentials volés, et atteinte d'actifs de valeur sur le réseau interne. L'attaquant (Parrot OS) opère depuis le même segment LAN, simulant un insider ou un attaquant ayant déjà franchi le périmètre externe.


## 7.2 Cyber Kill Chain — Phases Détaillées



### Phase 1 — Reconnaissance


Scan passif et actif du segment 192.168.50.0/24. Identification des machines actives, services exposés, versions logicielles, et systèmes d'exploitation. Outils : nmap, masscan, enum4linux, BloodHound (énumération AD).


### Phase 2 — Compromission Initiale


Exploitation d'une vulnérabilité sur Alma OS (services non patchés, configuration faible) ou brute-force d'un compte utilisateur faible sur Win10. Objectif : obtenir un shell ou un accès interactif sur la cible.


### Phase 3 — Post-Exploitation


Élévation de privilèges locale si nécessaire. Extraction de credentials en mémoire (Mimikatz, lsass dump). Reconnaissance interne : énumération des partages, des sessions, des trusts de domaine, des GPO applicables.


### Phase 4 — Mouvement Latéral (Pivoting)


Utilisation des credentials volés pour s'authentifier sur d'autres machines du domaine. Pass-the-Hash, Pass-the-Ticket (Kerberos), ou exécution à distance via SMB (PsExec, WMI). La machine compromise sert de relais vers des cibles de plus haute valeur.


### Phase 5 — Actions sur Objectif


Atteinte du but final : exfiltration de données depuis les partages SMB de SRV1, simulation de chiffrement (ransomware test), ou élévation vers Domain Admin. Cette phase valide la capacité de l'attaquant à contourner les défenses du cœur réseau.

📌 Annotation — Réalisme pédagogique : Ce scénario reflète l'approche réelle des attaquants : jamais de frontale sur la cible la plus dure. L'attaquant cherche la voie de moindre résistance, pivote, et progresse par étapes. C'est cette logique que le Purple Team doit comprendre pour construire des défenses efficaces à chaque étape de la chaîne.


# 8. PHASES DE CONSTRUCTION


Le déploiement de l'infrastructure suit un plan structuré en 8 phases. Chaque phase sera l'objet d'un document dédié, assurant la traçabilité complète du projet.


### Phase 1 — Hardening de SRV1


Audit avancé, GPO de sécurité de base, firewall optimisé, SMB hardening, service accounts dédiés, WEF, backup AD. Machine : SRV1.


### Phase 2 — Intégration au Domaine


Jonction de Win10 et Win11 au domaine lab.local. Vérification Kerberos, GPO applicables, authentification réseau. Machines : Win10, Win11, SRV1.


### Phase 3 — Déploiement Serveur Web


Installation d'Apache/Nginx, base de données (MySQL/PostgreSQL), configuration basique. Machine : Ubuntu.


### Phase 4 — Déploiement Honeypot


Configuration d'Alma OS avec services vulnérables intentionnels (vieil Apache, SMBv1, mots de passe faibles). Machine : Alma OS.


### Phase 5 — Déploiement Serveur Applicatif Vulnérable


Installation de SRV2 (OS à définir) avec services réalistes et vulnérabilités contrôlées. Machine : SRV2.


### Phase 6 — Déploiement SIEM


Installation et configuration de la stack de monitoring (Wazuh, ELK, ou solution maison). Centralisation des logs de toutes les machines. Machine : Fedora Security.


### Phase 7 — Intégration OpenKylin


Configuration réseau, tests de compatibilité, intégration au domaine ou workgroup. Machine : OpenKylin.


### Phase 8 — Validation du Scénario d'Attaque


Exécution contrôlée du Cyber Kill Chain depuis Parrot OS. Observation des logs, ajustement des défenses. Itération Purple Team. Machines : toutes.

📌 Annotation — Documentation itérative : Chaque phase génère un document distinct (Phase_1_Hardening_SRV1.docx, etc.). Cette modularité permet de réviser une phase sans impacter les autres, et démontre une approche professionnelle de gestion de projet technique.

# 10. CONSIDÉRATIONS DE SÉCURITÉ



## 10.1 Principes de Défense


Défense en profondeur : aucune mesure unique ne suffit. Chaque couche compense les faiblesses de la précédente.

Principe du moindre privilège : chaque compte, chaque service, dispose uniquement des droits strictement nécessaires.

Segmentation : bien qu'un seul LAN soit retenu initialement, la conception prévoit l'évolution vers une segmentation multi-zones.

Surveillance continue : l'absence d'alerte ne signifie pas l'absence d'attaque. Les logs sont la mémoire de l'infrastructure.

Backup et restauration : tout système peut être compromis. La capacité à restaurer rapidement est aussi importante que la prévention.


## 10.2 Menaces Identifiées


Compromission des credentials : Brute-force, phishing, extraction mémoire (Mimikatz). Mitigation : mots de passe forts, LAPS, audit connexions.

Attaque DHCP spoofing : Faux serveur DHCP redirigeant le trafic. Mitigation : autorisation AD, surveillance des leases.

Exploitation SMB : Vulnérabilités protocolaires ou mauvaise configuration. Mitigation : SMB signing, chiffrement, SMB1 désactivé.

Pivoting latéral : Utilisation d'une machine compromise pour atteindre d'autres cibles. Mitigation : segmentation, firewall hôte, détection anomalie.

Exfiltration de données : Sortie de données sensibles via Internet. Mitigation : contrôle des flux sortants, DLP, logs réseau.

📌 Annotation — Threat Modeling : Cette liste est un threat model préliminaire basé sur le framework STRIDE (Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege). Chaque phase de construction devra réviser et enrichir ce modèle.


# 11. ANNOTATIONS ARCHITECTURALES — RÉFLEXIONS DE L'ARCHITECTE



## 11.1 Pourquoi Hyper-V et pas VMware ou VirtualBox


Hyper-V est natif à Windows 11 Pro/Entreprise et offre une intégration parfaite avec les rôles Windows Server. Le switch virtuel externe permet du 'pass-through' réseau sans bridge manuel. Les checkpoints de production et la réplication Hyper-V sont des outils maîtrisés qui ont déjà sauvé lors de mises à jour ratées.


## 11.2 Le choix de Windows Server 2025 malgré sa jeunesse


Adopter une version 'bleeding edge' était un pari. Le risque était la stabilité des rôles réseau. Le gain était de monter en compétence sur la nouvelle stack avant que les clients ne migrent. Trois comportements dépréciés ont déjà été identifiés (RRAS GUI, netsh firewall, SMB1 par défaut off), permettant d'anticiper les projets de migration 2025 de futurs clients.


## 11.3 Ce que l'on ferait différemment


• Provisionner 100 Go dès le départ pour éviter l'intervention diskpart.• Créer un template VHDX 'sysprepé' de Server 2025 pour cloner le DC en 5 minutes.• Automatiser la création des vSwitches et des VMs via des scripts PowerShell déclaratifs (Infrastructure as Code).• Mettre en place un monitoring minimal dès la phase 1, pas en phase 6.


## 11.4 Compétences visées


• Administration avancée Windows Server 2025 (DHCP, DNS, RRAS/NAT, AD DS)• Gestion du stockage virtuel Hyper-V (VHDX, resize, diskpart)• Résolution de conflits DNS et configuration de forwarders• Écriture de scripts PowerShell reproductibles et idempotents• Documentation technique structurée pour audit et transfert de compétences• Pentest réseau (scan, enum, exploit, post-exploitation, pivoting)• Analyse forensique et réponse d'incident (Sysmon, EVTX, Sigma, Hayabusa)• Architecture Purple Team (itération attaque/défense)


## 11.5 Contexte d'utilisation du lab


• Tester des GPO et des scripts de déploiement logiciel avant application en production• Simuler des attaques réseau et valider la segmentation• Former des alternants et stagiaires sur l'administration Windows Server dans un environnement isolé• Préparer la certification AZ-800 (Administering Windows Server Hybrid Core Infrastructure)

# ANNEXE A — GLOSSAIRE


ACL : Access Control List — Liste de contrôle d'accès. Définit qui peut accéder à un objet (fichier, dossier, registre).

AD DS : Active Directory Domain Services — Service d'annuaire de Microsoft. Centralise l'identité, l'authentification et la gestion des ressources.

DC : Domain Controller — Contrôleur de domaine. Serveur hébergeant AD DS et authentifiant les utilisateurs du domaine.

DHCP : Dynamic Host Configuration Protocol — Protocole d'attribution automatique des paramètres réseau (IP, masque, passerelle, DNS).

DNS : Domain Name System — Système de noms de domaine. Traduit les noms (srv1.lab.local) en adresses IP (192.168.50.1).

GPO : Group Policy Object — Objet de stratégie de groupe. Règle de configuration appliquée aux utilisateurs et ordinateurs du domaine.

Kerberos : Protocole d'authentification réseau basé sur des tickets. Aucun mot de passe ne transite sur le réseau.

KDC : Key Distribution Center — Centre de distribution de clés. Service sur le DC qui émet et vérifie les tickets Kerberos.

NAT : Network Address Translation — Translation d'adresse réseau. Masque les IPs privées derrière une IP publique.

OU : Organizational Unit — Unité d'organisation. Dossier dans AD pour ranger les objets et appliquer des GPO ciblées.

RRAS : Routing and Remote Access Service — Service de routage et d'accès distant. Gère le NAT, le VPN, le routage inter-réseaux.

SACL : System Access Control List — ACL système. Définit les événements à auditer (qui a accédé à quoi, quand).

SMB : Server Message Block — Protocole de partage de fichiers Windows. Versions : SMB1 (obsolète), SMB2, SMB3 (chiffrement).

Sysmon : System Monitor — Outil Sysinternals loguant les événements système (processus, réseau, registre, drivers).

TGT : Ticket Granting Ticket — Ticket d'accès aux tickets. Délivré par le KDC lors de l'authentification initiale.

TGS : Ticket Granting Service — Ticket de service. Délivré par le KDC pour accéder à un service spécifique (SMB, HTTP, etc.).

WEF : Windows Event Forwarding — Transfert d'événements Windows. Centralise les logs de plusieurs machines vers un collecteur.
