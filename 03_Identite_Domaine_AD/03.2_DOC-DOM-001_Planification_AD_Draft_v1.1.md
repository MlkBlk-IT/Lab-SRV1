# 1. RÉSUMÉ EXÉCUTIF


Ce document constitue le plan de travail et le template de suivi pour la Phase 2 du laboratoire Hyper-V : la promotion de SRV1 en contrôleur de domaine (DC), la création de la forêt lab.local, et la jonction des postes clients Win10 et Win11 au domaine.

▸ Mission Phase 2Transformer SRV1 de serveur autonome en cerveau d'annuaire d'entreprise, avec authentification Kerberos, stratégies de groupe (GPO), et résolution DNS intégrée à AD DS.

▸ Pourquoi maintenant ?La Phase 1 (hardening réseau) doit être finalisée avant toute promotion DC. Un DC mal durci expose l'intégralité des credentials et des stratégies. La séquence hardening → AD DS est non négociable.


# 2. PRÉAMBULE & CONTEXTE



## 2.1 État de départ (Fin Phase 1)


SRV1 est en workgroup, durci pare-feu v3 (7/7 tests OK). DHCP, DNS, RRAS/NAT opérationnels. AD DS non installé. VMs clientes en workgroup, DHCP sur 192.168.50.0/24, DNS via SRV1.


## 2.2 Ce que change la Phase 2


SRV1 devient DC de la forêt lab.local.

DNS réintégré à AD DS (zones intégrées à l'annuaire).

Win10 et Win11 rejoignent lab.local, gérés par GPO.

Kerberos devient le protocole d'authentification unique.

SMB sur SRV1 sera RÉACTIVÉ, scoped LAN uniquement, car requis par SYSVOL. La migration vers SRV2 (Phase 5) ne concerne que le partage applicatif Lab-share, pas SYSVOL qui reste structurellement lié au DC.

# 3. FONDAMENTAUX THÉORIQUES


Concepts critiques à maîtriser avant d'agir. Théorie → Pratique → Documentation.


## 3.1 Active Directory Domain Services (AD DS)


Service d'annuaire distribué. Stocke objets dans NTDS.DIT. Expose LDAP (389/636) et Kerberos (88).

Forêt = lab.local (conteneur de plus haut niveau, schéma commun).

Domaine = lab.local (unité d'authentification et réplication).

DC = SRV1 (héberge NTDS.DIT + 5 rôles FSMO).


## 3.2 Kerberos


Protocole d'authentification par tickets. Si DNS incorrect, Kerberos échoue.

KDC sur chaque DC délivre les tickets.

TGT (port 88) : authentification initiale, valide 10h.

TGS : ticket de service pour accéder à une ressource.

SPN doit résoudre correctement → DNS intégré AD obligatoire.


## 3.3 DNS Intégré à AD DS


Zones intégrées AD stockées dans NTDS.DIT, répliquées via AD replication.

lab.local : intégrée AD, mise à jour dynamique sécurisée.

50.168.192.in-addr.arpa : intégrée AD, mise à jour dynamique sécurisée.

Forwarders conservés : 1.1.1.1, 8.8.8.8.


## 3.4 Group Policy Objects (GPO)


GPO liée au domaine : tous les objets du domaine.

GPO liée à une OU : objets de cette OU uniquement.

Ordre : Local → Site → Domaine → OU. Dernière GPO gagne.

Structure OU Phase 2 : Servers, Workstations, Users, Admins, ServiceAccounts.


## 3.5 Rôles FSMO


Schema Master, Domain Naming Master, RID Master, PDC Emulator, Infrastructure Master.

SRV1 détient les 5 rôles (DC unique).

# 5. PLAN D'ACTION DÉTAILLÉ


Ne passer à l'étape N+1 que si l'étape N est validée.


## 5.1 Étape 1 — Préparation & Sauvegarde


Créer snapshot Hyper-V 'Pre-Phase2-DC-Promotion'.

Documenter mot de passe DSRM dans un coffre hors VM.

Vérifier ipconfig /all sur Win10/Win11 : DNS = 192.168.50.1.

Critère de succès : Snapshot créé + DNS OK.


## 5.2 Étape 2 — Installation d'AD DS


Commande PowerShell (SRV1, admin élevé) :

Install-WindowsFeature AD-Domain-Services -IncludeManagementToolsImport-Module ADDSDeploymentInstall-ADDSForest -DomainName 'lab.local' -DomainNetbiosName 'LAB' -ForestMode 'WinThreshold' -DomainMode 'WinThreshold' -InstallDns:$true -CreateDnsDelegation:$false -DatabasePath 'C:\Windows\NTDS' -LogPath 'C:\Windows\NTDS' -SysvolPath 'C:\Windows\SYSVOL' -NoRebootOnCompletion:$false -Force:$true

▸ Paramètres critiques :

ForestMode/DomainMode 'WinThreshold' = Server 2016 functional level.

InstallDns:$true réintègre le DNS dans AD DS.

NoRebootOnCompletion:$false force le redémarrage.

Critère de succès : SRV1 redémarre, 'Welcome to lab.local', NTDS actif.

Rollback : Restaurer snapshot 'Pre-Phase2-DC-Promotion'.


## 5.3 Étape 3 — Ouverture Pare-Feu pour AD DS (CRITIQUE)


CORRECTION v1.1 : Le script v3 bloque tout inbound (BlockInbound). AD DS crée ses propres règles firewall lors de la promotion, mais elles peuvent être en conflit avec la politique globale. De plus, SMB (445) est actuellement bloqué — or SYSVOL/NETLOGON reposent sur SMB.

Commande PowerShell (SRV1, admin élevé) :

# Vérifier les règles créées automatiquement par AD DSGet-NetFirewallRule -DisplayName '*Active Directory*' | Select DisplayName,Enabled,DirectionGet-NetFirewallRule -DisplayName '*Kerberos*' | Select DisplayName,Enabled,Direction# Si manquantes ou désactivées, créer explicitement (LAN scoped uniquement) :New-NetFirewallRule -DisplayName 'Allow LDAP from LAN' -Direction Inbound -RemoteAddress '192.168.50.0/24' -LocalPort 389,636 -Protocol TCP -Action AllowNew-NetFirewallRule -DisplayName 'Allow Kerberos from LAN' -Direction Inbound -RemoteAddress '192.168.50.0/24' -LocalPort 88 -Protocol TCP,UDP -Action AllowNew-NetFirewallRule -DisplayName 'Allow Global Catalog from LAN' -Direction Inbound -RemoteAddress '192.168.50.0/24' -LocalPort 3268,3269 -Protocol TCP -Action AllowNew-NetFirewallRule -DisplayName 'Allow SMB from LAN (SYSVOL)' -Direction Inbound -RemoteAddress '192.168.50.0/24' -LocalPort 445 -Protocol TCP -Action AllowNew-NetFirewallRule -DisplayName 'Allow RPC Dynamic from LAN' -Direction Inbound -RemoteAddress '192.168.50.0/24' -LocalPort 49152-65535 -Protocol TCP -Action Allow

▸ Règles existantes à vérifier (créées par AD DS automatiquement) :

Active Directory Domain Controller - LDAP (TCP-In)

Active Directory Domain Controller - LDAP (UDP-In)

Active Directory Domain Controller - Secure LDAP (TCP-In)

Active Directory Domain Controller - Kerberos (TCP-In)

Active Directory Domain Controller - Kerberos (UDP-In)

File and Printer Sharing (SMB-In)

Critère de succès : Get-NetFirewallRule montre les règles AD DS actives ET la règle SMB 445 est autorisée depuis 192.168.50.0/24.


## 5.4 Étape 4 — Vérification Post-Promotion


FSMO : netdom query fsmo (5 rôles sur SRV1).

DNS intégré : Get-DnsServerZone | Where {$_.IsDsIntegrated -eq $true}

Enregistrements SRV : nslookup -type=SRV _ldap._tcp.dc._msdcs.lab.local

SYSVOL/NETLOGON : dir \\lab.local\SYSVOL et dir \\lab.local\NETLOGON

Partage SYSVOL : Get-SmbShare | Where {$_.Name -eq 'SYSVOL'}

Critère de succès : Les 5 vérifications retournent un résultat positif.


## 5.5 Étape 5 — Création Structure OU


New-ADOrganizationalUnit -Name 'Servers' -Path 'DC=lab,DC=local'New-ADOrganizationalUnit -Name 'Workstations' -Path 'DC=lab,DC=local'New-ADOrganizationalUnit -Name 'Users' -Path 'DC=lab,DC=local'New-ADOrganizationalUnit -Name 'Admins' -Path 'DC=lab,DC=local'New-ADOrganizationalUnit -Name 'ServiceAccounts' -Path 'DC=lab,DC=local'

Critère de succès : Get-ADOrganizationalUnit -Filter * liste les 5 OU.


## 5.6 Étape 6 — Création Utilisateurs & Groupes


NOTE : Mots de passe placeholder. En exécution réelle, utiliser Read-Host -AsSecureString — jamais de mot de passe en clair dans un script versionné.

$AdminPwd = Read-Host 'Mot de passe adm-malik' -AsSecureStringNew-ADUser -Name 'adm-malik' -SamAccountName 'adm-malik' -UserPrincipalName 'adm-malik@lab.local' -Path 'OU=Admins,DC=lab,DC=local' -AccountPassword $AdminPwd -Enabled $true -PasswordNeverExpires $false -ChangePasswordAtLogon $falseAdd-ADGroupMember -Identity 'Domain Admins' -Members 'adm-malik'$UserPwd = Read-Host 'Mot de passe user01' -AsSecureStringNew-ADUser -Name 'user01' -SamAccountName 'user01' -UserPrincipalName 'user01@lab.local' -Path 'OU=Users,DC=lab,DC=local' -AccountPassword $UserPwd -Enabled $true

Critère de succès : Get-ADUser -Filter * retourne adm-malik et user01. adm-malik est Domain Admin.


## 5.7 Étape 7 — Jonction Postes Clients


Add-Computer -DomainName 'lab.local' -Credential (Get-Credential) -Restart -Force

Get-Credential : saisir adm-malik@lab.local.

Redémarrage automatique (-Restart).

Critère de succès : Écran de connexion affiche 'lab.local'. Get-ADComputer liste WIN10$ et WIN11$.

Rollback : Remove-Computer -UnjoinDomainCredential (Get-Credential) -Restart -Force


## 5.8 Étape 8 — Tests Kerberos & GPO


Session user01@lab.local sur Win10/Win11.

klist tgt → ticket krbtgt/LAB.LOCAL.

gpresult /r → 'Applied Group Policy Objects' avec Default Domain Policy.

nslookup lab.local → 192.168.50.1.

Accès \\lab.local\SYSVOL\lab.local\ en lecture.

Critère de succès : klist TGT valide, gpresult OK, SYSVOL accessible.

Définition
